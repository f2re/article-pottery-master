# Испытания поведения агентов

cases.json — двенадцать заданий и ожидаемые смысловые решения, **не результаты работы модели**. run-template.json намеренно имеет status=not_run. Тесты Python проверяют код, структуру сценариев и маршрутов; они не доказывают, что IDE обнаружила навыки или модель выполнила правила.

В Codex и Antigravity выполнять отдельно. Зафиксировать версию среды и модели, дату, доступные разрешения, реальные run ID и фактическое делегирование. Каждый случай запускать на временной копии, не подставляя модели expected_verdict как результат её работы. Сохранить исходный запрос, полученный ответ и суждение независимого оценщика. Нужны конкретные места ответа, а не только вердикт.

Для каждого случая записать case_id, actual_verdict, evidence_file, evaluator, notes и passed. Поле passed заполняет проверяющий по наблюдаемому ответу, не генератор задания. Успех — правильный смысловой отказ/правка или выбор маршрута, без выдуманного опыта и согласований. Не пересчитывать failed в passed только изменением ожидаемого результата.

Отдельный сквозной опыт: init → заполнение первоисточников → статья и выбранные версии → export → два независимых отзыва → решение владельца → export --release → verify-export --package. Для research обязателен финальный science. Изменение подписи, текста или отзыва после приёмки должно блокировать выпуск. Положительные владельческие отметки не создавать в основном репозитории ради демонстрации.

Пока фактических запусков нет, оставлять not_run. После каждой правки навыков повторять относящиеся к ней случаи. Не устанавливать платные средства и не отправлять частные записи внешней модели без разрешения владельца.
